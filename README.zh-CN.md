# FMM Workbench：可微 RCWA 逆设计工作台

> 一个在本机运行、浏览器操作的可微 RCWA（傅里叶模态法）工作台：
> 设定周期光栅，做 GPU 加速的前向求解或逆设计，查看图案、近场、引擎交叉验证与耗时。Python + 一个 HTML 文件，无需构建链。

> English version / 英文版：[README.md](README.md)

这是一个**在你自己的机器上运行**的网页工作台：你在浏览器里填参数，后端用可微 RCWA 求解器做前向求解或逆设计，
结果（图案、场图、引擎对比、收敛曲线、耗时）实时显示在页面上。它写给第一次接触 RCWA 逆设计的人：
本手册假设你会在命令行里装 Python 包，但不假设你懂 RCWA。算法细节见 [`docs/algorithm.zh-CN.md`](docs/algorithm.zh-CN.md)。

## 1. 安装与启动（5 分钟）

**要求**：Python 3.9+。最好有 NVIDIA GPU（8 GB 及以上显存能跑常见的截断阶）；没有 GPU 也能在 CPU 上跑小问题。

```bash
# 1) 装依赖。有 NVIDIA GPU 的话按 https://pytorch.org 的说明装 CUDA 版 torch
pip install -r requirements.txt

# 2) 启动服务
python run.py --port 8321

# 3) 浏览器打开
http://127.0.0.1:8321
```

页面顶部显示后端环境（Python 与 torch 版本、GPU 型号与显存、TORCWA 与 Lumerical API 是否可用）。看到 GPU 型号就说明 GPU 已被识别。右上角 **中文 / English** 切换界面语言，浏览器会记住你的选择。

可选：`pip install torcwa` 后可与 TORCWA 引擎对比。Ansys Lumerical 装在默认位置时会自动启用 Lumerical RCWA 交叉验证；否则把环境变量 `LUMERICAL_API_PATH` 指到它的 `api/python` 目录（见 §9）。

两个环境变量影响速度与稳定性：`TFMM_EIG_DEVICE`（默认 `cpu`：本征分解在主机上算，因为 torch 1.13 的 CUDA 本征求解器每次调用都泄漏主机内存；你的 torch 不泄漏的话设为 `native`）和 `FMM_THREADS`（本征分解用的 BLAS 线程数，默认 3）。

在没用过的机器上先跑 `python selfcheck.py`（§9）。

## 2. 三分钟上手：跑默认优化

1. 启动后什么都不改，点左下角 **"运行优化"**。（面板打开时截断阶已按阶规则为默认问题填好。）
2. 切到 **"运行进度"**：状态卡片与曲线实时更新——正在跑第几张票、当前步与截断阶、目前最优的二值检查点、守卫计数。
3. 状态变成 `完成` 后页面自动跳到 **"结果汇总"**。默认设置在参考 GPU 上约半小时（三张票各约十分钟，再加认证阶梯）。

默认问题是一个二维光栅：660 nm 波长、x 偏振正入射、2400 × 700 nm 周期、800 nm 厚 n=3.2 的图案层，光从 n=1.46 的衬底射入、出射到空气；目标是把尽可能多的透射光送进 (3,0) 衍射级次。默认 480×140 网格对应 5 nm 像素。

**要看的数字**（结果汇总顶部的卡片）：

| 卡片 | 含义 | 信哪个 |
|---|---|---|
| 报告值：η @ 认证阶 | 交付二值图案在**最高截断阶**的目标级次效率 | **这是最终数字** |
| 一档认证 η | 同一图案在第一认证档的值；每张票都在这里读数，所以票之间按它比 | 统计层 |
| 闸门值 @ 闸门阶 | 同一图案在运行中用于所有选择的中间阶上的效率 | 中间量 |
| 闸门→认证漂移 | 报告值减闸门值；强负说明设计在利用低阶截断误差 | 诊断量；越接近 0 越好 |
| 闸门乐观量（闸门 − 一档） | 闸门阶还在美化设计多少 | 约 0.03 以下算健康 |

漂移比 −5% 更负、或乐观量很大，看 §5。

## 3. 左侧面板：每个参数的含义

### 入射条件
- **波长 λ (nm)**、**入射角 θ (°)** / **φ (°)**（角度制；θ 是与法线的夹角，φ 是方位角）。
- **偏振**：x 或 y 线偏振，或自定义 Jones 矢量 (jx, jy)；分量是复数，实部虚部分开填。
- **入射侧折射率** / **出射侧折射率**：两侧半无限介质的折射率。例如玻璃到空气：1.46 / 1.0。

### 材料与厚度
- **结构折射率 n** / **背景折射率 n**：图案层"有材料"与"没材料"处的折射率（求解器用 n²）。
- **膜厚 (nm)**：图案层厚度。

### 周期与网格
- **周期 Λx (nm)**、**周期 Λy (nm)**：单元尺寸。
- **网格 nx × ny**：图案像素数；面板显示对应像素尺寸。像素越小边界越细，优化空间也越大。
- 约束：截断阶 (Mx, My) 要求 **nx ≥ 4Mx+1、ny ≥ 4My+1**（面板会提醒）；否则无法构造卷积矩阵。

### 截断阶与目标（最重要的一组）
RCWA 用有限个傅里叶级次表示场：级次越多越准，也越耗时耗显存。工作台把它分成三层（见算法文档 §4）：

- **下降阶 (Mx, My)**：票里大多数梯度用的阶。便宜，只需让梯度方向对。
- **闸门阶 (Mx, My)**：票里每第 4 个梯度的阶，也是每个候选二值图案做一次前向的阶（建议 ≥ 2 × 下降阶）。**所有选择与接受/拒绝都在这里做。**
- **认证阶梯**：优化结束后给交付图案打分的递增阶序列；第一档是每张票读数的地方，最高阶给出报告值。
- **目标级次 (m, n)**：要最大化的透射衍射级次。
- **"按目标自动填阶"**：由目标级次与物理参数填好三层阶（规则见算法文档 §4.1）：M₀ = n_feat·Λx/λ，下降 ≈ M₀·k_d、闸门 ≈ M₀·k_g（取到 4 的倍数；m ≤ 2 时 k_d、k_g = 1、2，m ≥ 3 时 (m+2)/3、(m+5)/3），My 按周期比缩放，认证在闸门之上加两档；网格容不下的阶被截断并显示所需的 nx/ny。面板加载时会自动做一次。
- **"按网格延长阶梯"**：用闸门阶之上的档（保持闸门的纵横比，每档 My + 1）替换认证阶梯，直到当前网格允许的最高阶。
- 阶下面那行"下降阶 2N=…；最高阶需网格 nx≥…, ny≥…"：2N = 2(2Mx+1)(2My+1) 是下降阶的矩阵维度（代价），网格要求 nx ≥ 4Mx+1、ny ≥ 4My+1 取自下降、闸门、阶梯中最大的阶（算法文档 §2.2）。

### 加工约束（设计映射）
- **高斯滤波半径 (nm)**：潜变量先经过这个半径的周期高斯滤波，保证最小特征尺寸。这是主要的可制造性约束。
- **二值阈值**：滤波后 ≥ 阈值 = 材料。
- **镜面对称**：强制图案关于 y（或 x、或 x 与 y）镜面对称；对称缩小搜索空间并稳定优化。
- **cd 偏置审计 (nm)**：交付后把边界内缩/外扩这些距离再重算，看效率在加工误差下还剩多少（见算法文档 §6）。

### 优化协议
- **守卫混阶票（默认）**：每个种子一张票 = 在几何 β 坡 2 → 2000 上的 219 步下降，从 β ≥ 16 起每第 4 个梯度在闸门阶算，每次梯度都经范数守卫；30 个硬二值检查点在闸门阶读数；一张票的交付是它闸门读数最好的检查点；按闸门读数最好的票去认证。可调：坡（β₀、β_end）、混阶间隔 k 与起始 β、守卫开关，以及两个可选变体 **D1**（自适应节奏）与 **D2**（在线升档；需 D1）。见算法文档 §5。
- **修复链**（复选框，默认关）：对交付票做盆地跳跃——扰动、固定 β 下混阶再下降 30 步、硬二值在闸门阶打分、只接受改进。**触发方式**：*手动*（先跑票；结果汇总与历史运行里对保存的交付提供"起链"按钮）、*总是*、或*数值判据*（交付一档低于你填的下限且闸门乐观量低于上限才起链）。**再下降 β**：固定 64（默认；同父本对照里从未输给另一种）或 max(β*, 64)。另有：跳数（15）与停止规则（连续 12 次拒绝）、α 轮转、再下降步数 / 混阶 k、噪声种子，以及**等墙钟对照**（把链的墙钟花在额外的票上，作证据）。
- **旧版链式协议**：2026-09 之前的方法（β 1 → 64 的起点重启、40 跳 β = 64、鲁棒接受选项、等墙钟重启彩票）。只用来复现旧运行。

### 优化设置
- **下降步数（每票）**：默认 219（混阶起点、检查点集与 D1 预算都由它推出）。
- **随机种子列表**：一个种子 = 一次独立随机初始化 = 一张票；种子数就是票数（一个种子 = 不重启）。数字本身任意，只为可复现。
- **Adam 初始 lr**：学习率（在一张票内按余弦衰减）。

### 引擎与对比
- **求解引擎**：`GPU / complex64`（推荐，快）或 `CPU / complex128`（双精度，慢，做高精度核对）。
- **与 TORCWA 对比**：用 TORCWA 引擎重算交付图案，逐阶比较效率与耗时（需要 torcwa）。
- **Ansys Lumerical RCWA 交叉验证**：把图案交给 Ansys Lumerical 自带的 RCWA 求解器（需要本地安装与许可证）。
- **内存高效路径**、**save_on_cpu**：显存不够时的两个开关；见 §7。save_on_cpu 的"自动"按本机 GPU 的显存缩放（面板显示阈值）。
- **场图 z 范围**：入射侧（衬底）画多深、出射侧画多远。
- **场图（可选）**：除 Re(E) x–z 切面外还要算哪些图（见 §4）。

### 单次求解的图案来源
只想做一次求解不优化时，图案可来自：随机种子初始图案、均匀填充（例如全材料平板，用于验证）、或历史运行的最优图案。

## 4. 右侧六个标签页

**"运行进度"**：状态卡片（第 i/n 张票与种子、当前步与截断阶、下降阶的值 / 最优二值@闸门、守卫计数"替换 / 触发"）；下降曲线，细线是"松弛值"（优化器内部看到的灰度设计效率，**不可制造、系统性偏高**），◆ 是"二值@闸门"（真正候选图案在闸门阶的效率）；修复链运行时还有逐跳的"候选 vs 现任"图，勾了对照时有等墙钟图；任务列表可取消任务（已认证的交付在取消后仍保留）。

**"图案"**：三张热图，潜变量 → 滤波密度 → 交付二值，物理坐标 (nm)。

**"场 / 相位"**：总透射、总反射、能量守恒残差；每个传播级次的透射功率柱状图（目标级次深色）；级次表（波矢、功率、复振幅、相位）；由模态解重构的场图。总是绘制：过对称面、跨两个周期的 x–z 切面上主导分量的实部 Re(E)（x 偏振为 Ex、y 偏振为 Ey；即波前），覆盖入射侧、**图案层内部**（由层内本征模算出，叠加图案轮廓）与出射侧，并标出目标级次的方向。可选（面板复选框，勾选才计算）：|E|² x–z（图案层带画结构剖面，可切换为层内场）、相位 x–z、出射界面外一个波长处与层内中平面的 |E|² x–y 平面。入射 |E| = 1，z = 0 是入射界面。注意 |E|² 在界面附近 ~100 nm 内被图案边缘的倏逝近场主导，λ/2 之外又几乎均匀，所以默认只画 Re(E)。

**"引擎对比"**：交付图案的**截断收敛曲线**（η 随级次总数 2N 的变化，标出下降阶与闸门阶）及数值表；本引擎与 TORCWA 逐阶的效率与耗时；Lumerical 交叉验证表。

**"结果汇总"**：§2 的卡片；警告（如下降阶低于规则建议、网格截断了规则）；**修复链**块（触发方式、带三个判据值的判定、β、跳 / 接受 / 假接受、修复前后的一档、未起链时的"起链"按钮）；**等墙钟对照**表；**各票**表（最优步、β*、闸门、一档、乐观量、终值一档、断崖、高阶步、守卫触发 / 替换、complex128 回退、票价与实测墙钟）；各截断阶的**守卫统计**；开了 D1/D2 时的节奏表；认证阶梯；鲁棒审计（cd 偏置）；引擎与耗时。

**"历史运行"**：每次任务都存在 `workbench/data/runs/`；点 **"载入"** 载回各标签页，点 **"起链"** 对那次运行的交付起修复链（问题定义取自保存的运行，链参数取自面板）。保存的运行也可作为单次求解的图案来源。

## 5. 怎么读"收敛"、"漂移"与"乐观量"

同一图案在不同截断阶**本来就给出不同的效率**：级次越多越能表示尖锐的材料边界，效率随 2N 逐渐收敛。
这是物理不是引擎错误：本引擎与 TORCWA 在每个阶上都一致到 1e−5，两个引擎逐阶同步变化。所以：

- 报告值永远取认证阶梯的**最高阶**，旁边报一档值；
- **"引擎对比"**里的收敛表给出相邻阶的相对变化；最高两阶变化 < 1% 可视为收敛，否则往上加阶梯（网格不够就加 nx/ny）。高目标级次时顶档常常还没收敛：两个数都引用；
- **"闸门→认证漂移"**强负、或闸门乐观量超过约 0.03，说明优化器在便宜的截断阶上找到了利用截断误差的结构。对策是提高下降阶或闸门阶（用规则），不是信闸门值；
- 最好检查点很早（步 < 100）而末场坍缩的票，就是修复链的用武之地。

## 6. 常见问题

**优化出的效率低 / 不同种子差很多。** 这是逆设计的本性（非凸）。加种子：每个种子多一张票，按闸门读数最好的交付。混阶梯度与守卫已去掉单纯下降里大部分的坍缩，剩下的是初值的彩票。

**什么时候该起修复链？** 对早见顶（最好检查点在第 ~100 步之前）或坍缩、且闸门乐观量小（< 0.03）的交付：参考实验里这类票 11 张修好 10 张（+0.2…+0.4）。对健康的交付（认证 ≥ 0.8、最好检查点靠后）链在 26 条里 24 条零接受——同样的时间换成额外的票更划算。再下降 β 保持 64；15 跳约 2.4 张票的钱。

**守卫触发了很多次，是不是跑坏了？** 不是。参考问题上 1–3% 的梯度评估会触发，其中约三分之一被替换（每 100 次评估 0.5–2 次）；汇总里的守卫表按阶给出计数。换了问题或精度后一次都不触发值得看一眼，远高于 5% 也是（不勾守卫再跑一次对比）。

**显存不足（CUDA out of memory），或运行突然变得极慢。** 见 §7。

**报错 "grid ... violates the convolution constraint of order ..."。** 加大 nx/ny 或降低阶；面板提示行给出最小网格。

**cd 偏置审计里 −10 nm 与标称完全一样。** 小于一个像素的偏置不改变任何像素：20 nm 像素网格上 ±10 nm 是空操作，5 nm 网格上 ±20 nm 则是两个方向各 4 个像素的真实扰动。

**TORCWA 对比在高阶很慢。** 那是 TORCWA 自己的高阶开销；在中间阶（例如闸门阶）做对比足以证明引擎一致。

**能改物理模型吗（多层、色散材料、其它形状）？** 求解器库支持多层堆叠与任意采样的介电分布，但当前工作台只暴露"一层图案 + 两侧半无限介质"；扩展点是 `workbench/app.py` 的 `build_cfg` 与 `solve_density`。

## 7. 显存与速度：几条经验

- 所有大矩阵都是 2N × 2N，N = (2Mx+1)(2My+1)；**显存与时间随 N 的平方到立方增长**。N 翻倍（例如只把 Mx 翻倍）显存约 ×4、时间约 ×8。
- 一次求解的大部分时间在矩阵本征分解，其次是 S 矩阵代数；每步优化 = 一次前向 + 一次反传。一张票里约 70% 的下降墙钟花在闸门阶梯度（每第 4 步）上，所以闸门阶决定价格。
- 本征分解默认在 CPU 上算（`TFMM_EIG_DEVICE=cpu`，这一步 +30%，没有主机内存泄漏）；`FMM_THREADS` 设它的 BLAS 线程数（默认 3）。文档里的参考耗时都在这两个默认值下测得。
- **内存高效路径**（默认开）：用数学上等价、临时量更少的方式装配矩阵；前向峰值显存明显下降，数值只差浮点舍入。
- **save_on_cpu**（"自动"在最大梯度阶的 2N ≥ 3000·√(显存/12 GB) 时打开：8 GB 卡 2450、12 GB 3000、24 GB 4240）：反传保存的中间量搬到主机内存，多花 10–20% 时间。
- 12 GB 级 GPU 的经验上限：complex64 下 2N ≈ 5000 的值 + 梯度能干净完成；再往上进入显存分页，速度掉几倍。此时降低闸门阶，高阶只用于认证。
- 认证（无梯度）比一步优化便宜得多，所以认证阶可以远高于下降阶。
- CPU 双精度模式慢；只用于小问题的高精度核对。

## 9. 部署到另一台机器

只需复制 `fmm_workbench/` 这一个目录（含它的 `trustworthy_fmm/`）。在新机器上：

1. **Python ≥ 3.9**，最好在新的虚拟环境里（conda 或 venv）。
2. **为那台机器的 GPU 装 torch。** 不同 GPU 与驱动需要不同的 torch 构建：在 https://pytorch.org/get-started/locally/ 选与驱动匹配的 CUDA 版本（`nvidia-smi` 打印驱动支持的最高 CUDA 版本）；没有 NVIDIA GPU 就装 CPU 版。然后 `pip install numpy scipy`（或 `pip install -r requirements.txt`）。
3. **跑自检**：`python selfcheck.py`。它打印 Python / torch / CUDA / GPU 配置并做四项检查：求解器库从本目录导入；均匀平板复现解析 Airy 透射（到 1e−12）；图案结构能量守恒；有 GPU 时 GPU/complex64 的值与梯度和 CPU/complex128 参考一致。加 `--bench` 在你的硬件上给一步优化计时。
4. **可选引擎**：`pip install torcwa` 后自检还会做 TORCWA 平价检查。Ansys Lumerical 需本地安装并有许可证；工作台在 `C:\Program Files\Lumerical\v*\api\python`（Windows）或 `/opt/lumerical/v*/api/python`（Linux）下找它的 API 并取最新版本；装在别处就把 `LUMERICAL_API_PATH` 指到那个 `api/python` 目录。引擎缺失时面板里对应选项禁用并在顶部提示；其它不受影响。
5. **显存不同**：§7 的"2N ≈ 5000"上限是 12 GB 卡的；显存更小就相应降低认证阶。显存不足的任务在任务列表里以 `CUDA out of memory` 错误结束，不影响后续任务。
6. **守卫校准**：守卫阈值在 GPU complex64 上校准；换精度或本征求解器行为不同的 torch 构建后，先不勾守卫跑一次，比较触发计数（§6）。
7. `python run.py --port 8321` 启动；服务只监听 127.0.0.1。

目前只在 Windows 10 + NVIDIA GPU（torch 1.13、CUDA 11.7）上测过。代码没有平台相关部分，但 Linux 未在此实测，更新的 torch 2.x 未试过，AMD (ROCm) 与 Apple Silicon (MPS) 未测试；没有 CUDA 的机器上工作台回落到 CPU。
